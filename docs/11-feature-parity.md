# 11 - 三端功能对照矩阵（Feature Parity）

> **记录约定（写进每次功能开发的流程）**：在任何一端实现一个新功能后，
> 必须同步更新本表该行的三端状态列，并简注差异（交互形态、入口、平台
> 限制）。跨端统一时以本表为 checklist 逐行核对。只改平台机理相关的
> 实现细节（如后台保活方式）不算新功能，但差异说明列要更新。

图例：✅ 已实现 · ⚠️ 部分（备注差距）· ❌ 未实现 · ➖ 平台不适用 · ❓ 待查（未核实）

## 传输

| 功能 | 鸿蒙 | Android | iOS | 差异备注 |
|---|---|---|---|---|
| 实时进度（1Hz 轮询快照） | ✅ | ✅ | ✅ | 三端同走 `transfers()` 轮询 |
| **暂停 / 继续**（块边界闸门，断点保持） | ✅ 左滑「暂停」，Paused 态出「继续」 | ✅ 行内 Pause 按钮 | ⚠️ 绑定已有，无 UI | 引擎与绑定三端共享；iOS 需补按钮 |
| **终止**（cancel，已拷数据保留） | ✅ 左滑「终止」 | ✅ | ✅ | |
| 终态记录删除（单条） | ✅ 左滑「删除」 | ✅ 行内 Ignore/Forget | ✅ | |
| 多选删除记录（空心圆手势） | ✅ 长按多选 | ⚠️ 有选择无批量删除记录入口? | ❓ | Android 批量删除文件有，记录批删待查 |
| 断点续传（进程被杀后 resume） | ✅ | ✅ | ✅ | 引擎 SQLite checkpoint 三端共享 |
| resume 前自动重挂载来源后端 | ✅ | ❌ | ❌ | OHOS 独有（`ensureMountedForId`） |

| SMB 挂死防护（credits 泄漏 90s cap + 重连重试） | ✅ | ✅ | ✅ | 引擎层，三端共享 |
| 前台传输浮层（modal 进度） | ✅ | ✅ | ❌/➖ | iOS 无对应浮层 |
| 传输进度条每秒刷新但左滑稳定 | ✅ @Observed 行对象 | ✅ Compose 重组 | ✅ SwiftUI | 实现机制不同，效果一致 |
