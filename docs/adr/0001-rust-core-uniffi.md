# ADR 0001：Rust 内核 + 全原生 UI

- 状态：已采纳
- 日期：2026-11

## 背景

目标平台包含桌面三端、Android（含 TV）、iOS、鸿蒙（含 TV）。要求「全部原生」UI。
可选方案：

1. Flutter 单代码库（用户明确排除）
2. 纯原生，每端各写一套逻辑（Swift/Kotlin/C#/C++）
3. 原生 UI + 共享 Rust 内核（本决策）

## 决策

业务逻辑（VFS、协议、传输、索引）全部用 Rust 实现，通过 UniFFI 暴露给 Swift/Kotlin；
UI 与平台适配用各平台原生技术栈。

## 理由

- 文件管理最容易出 bug 的是分块、续传、SMB 兼容、错误分类；这些必须只有一份实现。
- UI 天然应该跟着平台走（导航、文件选择器、权限弹窗、TV 焦点），强行统一体验会更差。
- Rust 覆盖后续平台（Windows/Linux/鸿蒙）成本最低：只要编得过去，再写壳。
- 保留 CLI 与未来的 WASM/桌面端复用能力。

## 代价

- 团队需要 Rust 能力；FFI 边界设计要一次做对（见 ADR 0002/0003）。
- 不能享受 Flutter 的「一次 UI 到处跑」，每加一个平台仍有 UI 工作量。

## 弃用方案原因

- 纯原生逻辑多份：四个场景 × 两个平台 = 至少两套协议与传输实现，修 bug 不同步。
- Flutter：与「全部原生」的诉求冲突，且 tvOS/鸿蒙仍需原生壳。
