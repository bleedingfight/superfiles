# ADR 0004：iOS 定位为「文件提供者」，不是系统文件管理器

- 状态：已采纳
- 日期：2026-11

## 背景

「文件管理 App」在 iOS 上无法实现：没有全盘访问，看不到其他 App 沙箱，也没有系统级的文件关联管理。
如果按桌面产品思路设计，会在实现和审核两头受挫。

## 决策

iOS 版本的产品定位：

1. **自己的容器**通过 `UIFileSharingEnabled` 暴露到系统「文件」App；
2. 云盘/网络存储通过 **File Provider 扩展**挂进系统「文件」App；
3. 导入导出走 `UIDocumentPicker` 与 Share Extension；
4. 远程视频通过本地回环 HTTP 播放，不承诺「下载整个文件才能看」；
5. 文案与商店截图统一使用「文件与云存储浏览器 + 系统文件提供者」。

## 理由

- 符合系统能力，审核风险最低。
- 用户的核心诉求（在系统「文件」里看到 NAS/云盘）恰好由 File Provider 满足。
- 避免承诺「清理/管理整机文件」这类做不到的功能。

## 代价

- 需要在 M2 额外实现 File Provider 扩展（约 1–2 周）与 App Group 容器共享。
- 后台传输能力有限，必须在 UI 上明确提示。
